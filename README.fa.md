# 🛡 سرو (Sarv)

**آنتی‌ویروس متن‌باز برای سرورهای وب لینوکسی**، با تمرکز روی آلودگی‌های از طریق وب: وب‌شل‌ها، تزریق کد PHP، دستکاری فایل‌های وردپرس/لاراول، و ماندگاری مهاجم پس از نفوذ.

یک باینری استاتیک Go — بدون وابستگی، بدون CGO. ساخته‌شده برای سرورهای میزبانی که ده‌ها سایت وردپرس و لاراول را اجرا می‌کنند.

> English: [README.md](README.md)

## چرا سرو؟

امضاهای ClamAV بیشتر وب‌شل‌های PHP را نمی‌گیرند و Linux Malware Detect برای اسکن مجدد درخت‌های بزرگ کند است. سرو دقیقاً برای مدل تهدید میزبانی وب ساخته شده:

- **لحظه‌ای** — یک ناظر `inotify` هر فایل PHP جدید/تغییریافته را چند ثانیه پس از ایجاد اسکن می‌کند (همان لحظه‌ای که وب‌شل آپلود می‌شود).
- **اسکن مجدد سریع** — کش فایل‌های سالم در SQLite (کلید `path+size+mtime`) باعث می‌شود اسکن کامل صدها هزار فایل بعد از بار اول در چند ثانیه انجام شود.
- **صحت‌سنجی، نه فقط امضا** — فایل‌های هسته و پلاگین وردپرس با چک‌سام رسمی wordpress.org مقایسه می‌شوند؛ فایل‌های PHP لاراول در `public/`/`storage/` با baseline سنجیده می‌شوند.
- **فراتر از پوشه وب** — بررسی اختیاری سلامت سیستم‌عامل، ماندگاری مهاجم را می‌گیرد (باینری‌های تروجان‌شده، دراپرهای `/tmp`، کران/سرویس مخفی، تغییر کلید SSH، پردازش ماینر).
- **توصیه‌های عملی** — ماژول advisor یافته‌ها را به توصیه‌های مشخص امنیتی تبدیل می‌کند.

## زنجیره تشخیص

هر فایل از این مسیر عبور می‌کند: **کش فایل سالم ← قوانین امضا ← هیوریستیک**، به‌علاوهٔ صحت‌سنجی در اسکن کامل.

- **قوانین امضا** — قوانین YAML گلچین‌شده برای وب‌شل‌های رایج PHP (WSO، c99، r57، b374k، alfa، FilesMan…)، دراپرهای مبهم‌سازی‌شده (`eval(base64_decode(...))`، پکرهای goto/`$GLOBALS`)، فراخوانی `system()` و توابع متغیر با ورودی درخواست، هندلرهای مخرب `.htaccess`، ماینرهای JS و بیشتر. به‌صورت embed شده ارائه می‌شود؛ با `/etc/sarv/rules.d/*.yml` قابل گسترش است.
- **هیوریستیک** — آنتروپی، خطوط تک‌خطی غول‌آسا، بلاک‌های base64/hex، PHP داخل `uploads/`، پسوند دوگانه (`.jpg.php`)، فایل PHP مخفی، timestomping.
- **صحت‌سنجی وردپرس** — چک‌سام رسمی هر فایل تغییریافته یا اضافی در `wp-admin/` و `wp-includes/` را علامت می‌زند.
- **baseline لاراول** — فایل PHP جدید/تغییریافته در `public/` یا `storage/` پس از اولین اسکن (سالم) گزارش می‌شود.

## زمان‌بندی اسکن

| لایه | زمان | پوشش |
|---|---|---|
| لحظه‌ای | چند ثانیه پس از تغییر فایل | فایل‌های پرریسک جدید/تغییریافته با inotify |
| سریع | هر ساعت | پوشه‌های uploads / wp-content / public + فایل‌های اخیراً تغییریافته |
| کامل | هر شب (۳ بامداد، قابل تنظیم) | همه‌چیز + چک‌سام وردپرس + syscheck + advisor |

همه داخل `sarv monitor` اجرا می‌شوند، با `nice` و io بی‌کار تا روی سایت‌های پروداکشن اثر نگذارند.

## نصب

</div>

```bash
git clone https://github.com/samanzamani/sarv && cd sarv
sudo make install         # ساخت و نصب باینری + config + سرویس systemd
```

<div dir="rtl">

سپس:

</div>

```bash
sudoedit /etc/sarv/config.yml     # مسیرهای اسکن، توکن/چت/پروکسی تلگرام
sarv web set-password             # اختیاری: رمز پنل وب
sarv scan --full                  # اسکن baseline اولیه
systemctl enable --now sarv       # اسکن لحظه‌ای + زمان‌بندی‌شده
sarv notify test                  # تست اعلان تلگرام
```

## دستورات

</div>

```
sarv scan [paths...] [--full]   اسکن بدافزار (‏--full شامل صحت‌سنجی وردپرس، syscheck، advisor)
sarv monitor                    سرویس لحظه‌ای: inotify + اسکن زمان‌بندی‌شده (+ پنل وب)
sarv sites                      لیست سایت‌های وردپرس/لاراول شناسایی‌شده
sarv syscheck                   سلامت سیستم‌عامل: باینری‌ها، دراپر /tmp، persistence، پردازش‌ها
sarv advise                     توصیه‌های امنیتی hardening
sarv report [--status open]     نمایش یافته‌ها
sarv quarantine list|add|restore|delete
sarv web [set-password]         اجرا/پیکربندی پنل وب
sarv notify test                ارسال پیام تست تلگرام
```

## واکنش

پیش‌فرض **گزارش + قرنطینه دستی** است — یافته‌ها ثبت و اعلان می‌شوند و تا وقتی خودت اقدام نکنی چیزی دست نمی‌خورد. قرنطینه فایل را با متادیتای کامل (پرمیشن، مالک، هش) به `/var/lib/sarv/quarantine/` منتقل می‌کند تا `restore` دقیقاً برش گرداند. با `quarantine.auto: high|all` قرنطینه خودکار فعال می‌شود.

## پنل وب (اختیاری)

پیش‌فرض خاموش. با `web.enabled: true` (یا `sarv web`) یک پنل مستقل — **جدا از وب‌سرور سرور (Apache/OpenLiteSpeed/FrankenPHP)** — با داشبورد، یافته‌ها، قرنطینه، اسکن دستی، سلامت سیستم، توصیه‌ها و تنظیمات ارائه می‌شود. ورود اجباری است (bcrypt)؛ روی `127.0.0.1` bind کن و از طریق تونل SSH وصل شو، یا برای دسترسی بیرونی TLS و قانون فایروال بگذار.

## اعلان‌ها

تلگرام Bot API با پشتیبانی اختیاری **پروکسی HTTP یا SOCKS5** (‏`proxy_url`) — مفید جایی که `api.telegram.org` مسدود است. یافته‌های یک اسکن در یک پیام واحد تجمیع می‌شوند.

## نکات و محدوده

- سرو **تشخیص و گزارش** می‌دهد؛ هرگز خودش سایت‌ها یا سیستم‌عامل را تغییر نمی‌دهد (فقط قرنطینه، آن‌هم وقتی فعالش کنی).
- مکمل است، نه جایگزین `rkhunter`/`AIDE`/WAF.
- پوشش امضاها همیشه در حال تکامل است — PR با قوانین جدید و نمونه‌های تست پذیرفته می‌شود.
